# Постоянный WireGuard без автоматического перехода на AWG

Это дополнительный режим, который включается **после** установки DualVPN. По умолчанию
комплект оставляет ручное переключение между туннелями. Здесь основной маршрут
навсегда закрепляется за WG: краткий обрыв не выбирает AWG, а служба продолжает
проверять и повторно поднимать только WG. AWG может оставаться поднятым для
удалённого управления, но не становится основным маршрутом.

## Включение

Сначала убедитесь, что WG-профиль действителен, на сервере зарегистрирован peer
роутера, в частном конфиге задан `PersistentKeepalive`, а адрес для проверки
`vpnmode.main.probe_ip` доступен **через WG** и не совпадает с VPN endpoint.
Адрес проверки, CIDR и DNS выбирайте для своей сети; личные значения в этом
репозитории не хранятся.

После двухэтапной быстрой установки LT300:

```sh
/root/cudy-dualvpn-stage2/enable-persistent-wg.sh
```

При полной ручной установке из каталога, переданного в `/tmp`:

```sh
/tmp/Cudy-LT300-OpenWrt-DualVPN-Kit/scripts/enable-persistent-wg.sh
```

Скрипт сохраняет прежний `vpnmode` в `/root`, устанавливает службу с `procd`,
фиксирует `mode=wg`, ставит `auto_failover=0` и включает автозапуск. После
`sysupgrade` файлы службы сохраняются через `/etc/sysupgrade.conf`, если выбрано
сохранение настроек. Чистая прошивка с `-n` требует повторной установки.

## Проверка и перезагрузка

```sh
uci -q get vpnmode.main.mode
uci -q get vpnmode.main.auto_failover
/etc/init.d/vpn-wg-persistent enabled
ubus call service list '{"name":"vpn-wg-persistent"}'
ip -4 route show default
wg show wg0 latest-handshakes
ping -I wg0 -c 5 "$(uci -q get vpnmode.main.probe_ip)"
logread | grep vpn-wg-persistent
```

В основном маршруте ожидается `dev wg0`. После проверки по Ethernet выполните
`reboot`, дождитесь SSH и повторите команды. На LT300 время при загрузке может
исправляться из LTE-модема; до синхронизации показанный возраст handshake может
быть неверным. Проверяйте одновременно передачу пакетов, дату UTC и свежие логи.

Проверка происходит каждые 30 секунд. После трёх подряд отрицательных проверок
служба циклически перезапускает только WG с ограничением частоты, но не прекращает
новые попытки. Наличие рабочего трафика важнее одного старого timestamp.

## Замена частного WG-профиля

Передавайте профиль только на свой роутер, не в git. Сначала сделайте закрытый
backup. Остановите службу, чтобы она не мешала импорту, затем используйте
штатный импортёр с **собственным** файлом в `/tmp`:

```sh
/etc/init.d/vpn-wg-persistent stop
/tmp/Cudy-LT300-OpenWrt-DualVPN-Kit/scripts/configure-wireguard-from-conf.sh \
  /tmp/my-wireguard.conf wg0
rm -f /tmp/my-wireguard.conf
ifdown wg0
ifup wg0
/usr/sbin/vpn-apply-route wg
/etc/init.d/vpn-wg-persistent start
```

После смены адреса или ключей peer обновите и на сервере. Импортёр кладёт IP из
строки `DNS` в DNS-интерфейса, а доменное имя — в `dns_search`; **DHCP-настройки
LAN/Wi-Fi он не меняет**. Если клиентам нужен новый DNS, задайте его через DHCP
отдельно и проверьте выдачу на клиенте. Временный профиль и backup могут содержать
секреты; храните их только закрыто.

## Возврат к ручному DualVPN

```sh
/etc/init.d/vpn-wg-persistent stop
/etc/init.d/vpn-wg-persistent disable
```

После этого LuCI-кнопки и `vpn-use-awg` снова могут выбирать резервный режим.
Пока служба работает, она отменит ручной выбор AWG на ближайшей проверке. Это
намеренная особенность фиксированного режима, а не автоматический failover.
